# e-shutov.ru

Личный сайт-досье Евгения Шутова. Русская и английская версии.
Статические файлы, без фреймворков и без внешних зависимостей: шрифты лежат локально,
запросов на сторонние домены сайт не делает вообще.

## Как устроено

```
src/content.mjs    ← весь текст сайта, RU и EN. Правится только здесь
src/render.mjs     ← разметка страницы
src/styles.css     ← дизайн-система
src/app.js         ← меню, подсветка навигации, появление блоков
src/favicon.svg    ← иконка вкладки
build.mjs          ← сборка

index.html         ┐
en/index.html      │
404.html           ├ результат сборки — эти файлы и заливаются на хостинг
assets/            │
sitemap.xml        │
robots.txt         ┘
```

## Правка и сборка

Текст меняется в `src/content.mjs` — объект `ru` и его зеркало `en`.
Структуры обеих версий должны совпадать. После правки:

```bash
node build.mjs
```

Требуется только Node.js — ни `npm install`, ни сборщиков.

## Публикация на reg.ru

Сайт полностью статический, поэтому достаточно скопировать файлы в корень сайта
(на reg.ru это обычно `/public_html` или `/www/e-shutov.ru`) по FTP или через файловый
менеджер панели управления.

Заливать нужно:

```
index.html
404.html
favicon.svg
robots.txt
sitemap.xml
en/
assets/
```

Папки `src/` и файла `build.mjs` на хостинге быть не должно — это исходники.

Старую React-сборку (`assets/index-*.js`, `assets/index-*.css`) перед заливкой удалите,
иначе в папке `assets` останутся файлы от предыдущего сайта.

## Что можно добавить, и сайт сам это подхватит

Сборка проверяет наличие файлов и включает соответствующие блоки только тогда,
когда файл действительно лежит на месте. Ничего не сломается, если файла нет.

| Файл | Что появится |
|---|---|
| `assets/img/portrait.webp` | Портрет на первом экране. Без него первый экран чисто типографический. Фигура, вырезанная по контуру, с прозрачным фоном, 1120×1440 |
| `assets/shutov-cv.pdf` | Кнопка «Резюме PDF» на первом экране |
| `assets/img/gallery-*.webp` | Снимки раздела «Фотографии». Состав, подписи и порядок задаются в `gallery` в `src/content.mjs`, размеры и точка кадрирования — в `shared.photos` |
| `assets/img/work-intervision.jpg` | Фотография в блоке «Интервидение-2025» |
| `assets/img/work-sco.jpg` | Фотография в блоке «Бизнес-инкубатор ШОС 2025» |
| `assets/img/work-bridge.jpg` | Фотография в блоке «Russia Bridge Program» |
| `assets/img/work-rakez.jpg` | Фотография в блоке «RAKEZ» |
| `assets/img/work-agora.jpg` | Фотография в блоке «AGORA Global Business Club» |

Фотографии проектов — горизонтальные, 16:9, от 1600 px по ширине.
На сайте они показываются обесцвеченными и наливаются цветом при наведении.
Сейчас этих файлов нет: все снимки собраны в отдельной цветной галерее.

Карточки для соцсетей (`assets/img/og-*.png`) собираются из того же портрета
и заголовка обложки: `node tools/genog.mjs`. После замены портрета их нужно
пересобрать, иначе в мессенджерах останется старый снимок.

После добавления файлов снова выполните `node build.mjs`.

## Что учтено

- Две языковые версии с корректными `hreflang` и переключателем
- Микроразметка `schema.org/Person`, `sitemap.xml`, `robots.txt`
- Тёмная тема по системной настройке
- Стиль для печати: страница печатается и сохраняется в PDF как аккуратное резюме
- Клавиатурная навигация, ссылка «Перейти к содержанию», `prefers-reduced-motion`
- Шрифты Onest и IBM Plex Mono подключены локально (200 КБ на всё) —
  сайт не делает ни одного запроса на сторонние домены
- Движение: отсчёт цифр, рост полос занятости, последовательное появление
  меток на карте. Всё отключается при prefers-reduced-motion

## О формулировке должности

По резюме: руководитель российского офиса (Country Manager, Russia) с августа 2025 года,
генеральный директор юридически с января 2026 года. В открытых источниках основателем
Consult Invest ITIC указана Татьяна Селиверстова, поэтому на сайте в заголовке стоит
«руководитель российского офиса», а статус генерального директора вынесен уточняющей
строкой в блоке опыта. Так формулировка точна и выдерживает проверку.

## Оформление

Современный гротеск Onest с кириллицей от разработчика, а не дорисованной.
Холодная светло-серая бумага, кобальтовый акцент (#1e4bad, контраст 7,4:1).
Засечных шрифтов на сайте нет: они одевали бы человека, который ведёт проекты
сейчас, в костюм из позапрошлого века.

## Язык

Русский текст — основной, английский — перевод, а не наоборот. Обе версии написаны
как самостоятельные тексты: без калек вроде «под ключ» применительно к делегациям
и без кальки «бразильский профиль». Специализация называется прямо — Латинская Америка.

## Как готовился портрет

Фон убран нейросетевой маской (rembg, модель birefnet-general). Цвет на
полупрозрачной кромке пересчитан от самого человека (pymatting), иначе на
волосах оставалась кайма от студийного фона. В исходном кадре левый рукав
обрезан краем снимка: холст расширен влево, недостающая полоса рукава
закрашена тоном ткани у самого края по плавному контуру плеча.

Затем поправлены свет и цвет: баланс белого выставлен по рубашке (в
исходнике она уходила в синеву), снимок высветлен кривой — он был
недосвечен, — крупные перепады яркости на лице и пиджаке слегка
выровнены, блик на лбу приглушен до тона кожи. Черты лица и форма не
менялись.

Картинки отдаются с версией в адресе (`?v=<хеш>`), поэтому после замены
файла под тем же именем кеш браузера не показывает старый снимок.

## Выгрузка на хостинг

```
DEPLOY_USER=<логин панели> tools/deploy.sh <файл с паролем> [коммит]
```

Сценарий входит в панель ISPmanager по обычному HTTPS и заливает файлы
через ее загрузчик: FTP и SSH из облачного окружения недоступны. Пароль
читается из файла и в репозитории не хранится. Со вторым аргументом
выгружаются только файлы, изменившиеся с указанного коммита; в конце
сценарий сверяет то, что отдает сайт, с локальной сборкой.
