# Передача проекта: сайт Consult Invest ITIC

Файл для новой сессии Claude. Здесь собрано, что за проект, что заказчик просил, чем был недоволен и в каком состоянии всё сейчас. Прочитай его целиком перед тем, как что-то делать.

---

## 0. Главное за 30 секунд

- **Итог прошлой сессии заказчик оценил как «говно полное».** Цитата: «что цвета что баги что тупо тот же дизайн оставил». Код и контент в порядке, но **визуально сайт остался старым**: тот же светлый фон, те же тонкие линии и списки, та же типографика. Новые блоки добавлялись поверх старой раскладки, и новый дизайн так и не появился.
- **Задача новой сессии: сделать заметно другой, современный, «статусный» и иммерсивный сайт.** Уровень – сайты международных консалтинговых и инвестиционных компаний. Нужно меньше текста, больше крупного изображения и движения, необычные элементы, которые плавно приближаются и отдаляются.
- **Контент, данные, админку и проверки переиспользуй.** Выбрасывать не нужно ничего, кроме визуального слоя: CSS и раскладок.

## 2. Стек и команды

- **Сайт:** Astro 7 (статическая сборка), контент в Markdown (`src/content/`), Decap CMS (`public/admin/`), хостинг Netlify.
- **Движение:** Motion (ванильный API `animate/scroll/inView` из пакета `motion`), файл `src/scripts/motion.ts`. React и `@astrojs/react` подключены, но островов пока нет.
- **3D-глобус:** `cobe`, в `src/components/Geography.astro`. Если глобус недоступен, показывается плоская SVG-схема.
- **Фото:** обрабатываются `sharp` при сборке (`scripts/process-images.mjs`, запускается как `prebuild`). Исходники лежат в `media-src/`, результат в `public/media/` (эта папка в gitignore).
- **og:image:** генерируются при сборке (`src/pages/og/[...slug].png.ts`, satori + resvg).
- **QR-коды:** пакет `qrcode`, компонент `src/components/Qr.astro`.

```bash
npm ci
npm run dev            # astro dev (в Astro 7 это фоновый демон: npx astro dev stop/status/logs)
npm run build          # prebuild обработает фото, потом astro build
npm run lint:copy      # проверка текстов по «Редактуре»
npm run check:links    # внутренние ссылки, wa.me
node scripts/screens.mjs <папка> /opt/pw-browsers/chromium   # 20 скриншотов: 5 страниц × 1440/390 × светлая/темная
PUBLIC_SHOW_REVIEW_NOTES=true npm run build                   # сборка с пометками «На согласование»
```

Админка локально: `npm run cms` (decap-server), затем `/admin/index.html`.

## 3. Жесткие правила (обязательны в любом дизайне)

1. **Факты, цифры, годы, имена, цитаты – только из ТЗ и презентации.** Чего нет, оставлять `TODO` в коде и не выводить на сайт. Ничего не выдумывать.
2. **Редактура текстов:**
   - без «ё»;
   - внутри предложений только короткое тире «–»; диапазоны без пробелов: «25–26 апреля»;
   - кавычки «елочки», внутри „лапки“;
   - название только «Consult Invest ITIC»;
   - запрещены «является», «осуществляет», «Таким образом», «не X, а Y», «т.г.»;
   - каждая цифра с пояснением;
   - неразрывные пробелы в телефонах, «$700 млн» и т. п.
   - Проверяет `npm run lint:copy`. Если установлен скилл avoid-ai-writing, прогонять им новые тексты.
3. **Логотипы не вырезать из скриншотов.** Брать только из исходников: официальный сайт, Wikimedia Commons, в крайнем случае агрегатор. Всё, что не найдено, вносить в `docs/LOGOS_TODO.md`.
4. **RAKEZ не показывать как действующий статус:** контракт закрыт.
5. **Не выводить «6 офисов» и «6 стран».** Реальных офисов два: Москва и Ташкент. В остальных странах работают представители: Китай (Нанкин и Циндао), Казахстан, Кыргызстан, Саудовская Аравия. Номер Саудовской Аравии не подтвержден, поэтому строка идет без номера.
6. **Спорные блоки оборачивать в `<Review note="…">`.** Это пометка «На согласование» для Татьяны. Видна при `PUBLIC_SHOW_REVIEW_NOTES=true` (на Netlify включено). Список вопросов ведется в `docs/REVIEW.md`.
7. **Коммиты:** один блок – один коммит, в конце строки `Co-Authored-By` и `Claude-Session`.
8. **Движение на усмотрение, чем смелее, тем лучше.** Решение заказчика важнее раздела 2а ТЗ: там движение сильно ограничено, заказчик сказал «не верь брифу в этом моменте». Обязательно: `prefers-reduced-motion` отключает всё, контент виден без JS.
9. **Анимации, которые заказчику понравились, оставлять.** Цитата: «Анимации топ… помни это тоже!» Будет спорное предложение убрать часть – относиться критически: сайт должен быть необычным и интересным.

## 4. Хронология: что заказчик просил

1. **Аудит старого сайта на Tilda** с дизайн-скиллами, /llm-council. Пожелания руководителя:

2. **Выбран вариант «свой сайт».** Правки основного Claude:

   - два входа: бизнес и госструктуры;

3. **Прототип.** Первый вариант отвергнут как шаблонный. Попросил сделать узнаваемым рядом с презентацией, потом «ОТ ПРЕЗЕНТАЦИИ ВО ВСЕМ ОТХОДИТЬ».

   - два реальных офиса, остальные – представители;

   - фото мероприятий;

6. **Установил impeccable, Playwright MCP, taste-skill, framer-motion-skill.**
7. **ТЗ `redesign-brief.md`, этапы 1–6** (гигиена, доказательства, композиция, кейсы, страницы, мобильная версия и скорость) – сделаны.

11. **Финальная реакция:** «цвета, баги, тот же дизайн». Сессия закрыта.

## 5. Чем заказчик был недоволен (не повторять)

- **Дизайн остался прежним.** Светлый почти белый фон, тонкие линии, списки «заголовок + текст + линия», таблицы-строки. Каждая секция выглядит одинаково. Новые блоки в той же стилистике не воспринимаются как редизайн.
- **Цвета.** Бледная палитра (#F7F8F6, серый текст, зеленый только на кнопках) воспринимается как скучная и дешевая. Какие именно цвета не понравились, заказчик не уточнил – спросить.
- **Баги.** Конкретные не названы. Известное из скриншотов:
  - плашки «На согласование» пунктиром выглядят как мусор;
  - в сцене глобуса список контактов высокий, верх может срезаться на невысоких экранах;
  - на мобильном заголовок первого экрана закрывает рукопожатие;
  - неровные размеры логотипов;
  - первый кадр глобуса без точек, пока грузится текстура.
- **Карта** (плоская SVG) – «хуйня». Глобус cobe сделан, но оценки ему не было.
- **Слишком много текста и служебных данных.** Нужно меньше абзацев, больше визуальных акцентов.
- **Шаблонность.** «Хуже вайб-коденного»: всё выглядит собранным по чек-листу.
- **Остановки.** Злился, когда сессия ждала подтверждения: «не останавливайся вообще, пока всё совсем не сделаешь».
- **Лишний поиск.** Злился на лишние траты: «ты щас кредиты на эту хуйню тратишь» – о поиске 37 логотипов. Нужно проще: взять узнаваемые найденные, остальные позже.
- **Правки субагентов внутри прямых цитат** – нельзя менять цитаты.
